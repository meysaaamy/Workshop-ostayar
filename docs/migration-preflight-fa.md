# پیش‌بررسی غیرمخرب دادهٔ Room قدیمی

ابزار `parity/migration/preflight.py` فقط یک ابزار تشخیصی آفلاین است، **نه مهاجرت Room، نه برنامهٔ Android و نه تأیید سلامت کامل داده**. فقط یک تصویر سازگار از پایگاه قدیمی نسخهٔ ۲ را با SQLite در حالت `mode=ro` و `query_only` می‌خواند؛ هیچ رکوردی را حذف، اصلاح، گرد یا تبدیل نمی‌کند. گزارش فقط تعداد رکوردها و ایرادها را دارد و نام یا محتویات رکوردهای شخصی را چاپ نمی‌کند.

```sh
python3 parity/migration/test_preflight.py
python3 parity/migration/preflight.py /path/to/offline-copy/workshop-ledger.db
```

خروجی با کد ۰ یعنی در **همین بررسی محدود** ایرادی مشاهده نشده، ۱ یعنی حداقل یک ایراد دیده شده و ۲ یعنی فایل یا ابزار قابل خواندن نبوده است. صفر به معنی امن بودن مهاجرت نیست. کپی باید با روش سازگار با SQLite شامل WAL تهیه شود؛ کپی سادهٔ فایل اصلی هنگام اجرای برنامه ممکن است داده‌های commitشدهٔ WAL را جا بیندازد. بهتر است از سازوکار backup خود SQLite روی یک منبع قابل دسترس استفاده شود. `mode=ro` می‌تواند در برخی وضعیت‌های WAL به فایل‌های جانبی یا دسترسی دایرکتوری نیاز داشته باشد؛ ابزار را روی تنها نسخهٔ داده اجرا نکنید. DataStore و بکاپ‌های خودکار جداگانه‌اند و این ابزار آنها را نمی‌خواند.

## آنچه بررسی می‌شود

- وجود جدول‌ها و ستون‌های مورد نیاز همین بررسی، نسخهٔ SQLite، تعداد ردیف، پول/نرخ عددی متناهی و صحیح در محدودهٔ صفر تا ۹۹۹٬۹۹۹٬۹۹۹٬۹۹۹، تاریخ جلالی معتبر ۱۲۰۰ تا ۱۷۰۰ بر اساس fixture موتور قدیمی، و بازهٔ معکوس واریزی.
- دسته‌بندی حضور با بررسی JSON: علامت، ساعت مضرب نیم، ساعت معتبر قدیمی غیرمضرب نیم، و مقدار غیرقابل تشخیص/خارج محدوده. ساعت معتبر غیرنیم‌ساعتی مشکل محسوب نمی‌شود. دسته‌بندی جایگزین حفاظت از رشتهٔ اصلی JSON یا مهاجرت واقعی نیست.
- آزمون خودکار از SQL استخراج‌شدهٔ APK یک پایگاه مصنوعی می‌سازد؛ عدم تغییر بایت فایل بدون WAL، خواندن تراکنش commitشده در WAL، خطای طرح/نسخه، مرزها و شمارش مقدار ۱٫۲۵ را چک می‌کند. آزمون روی پایگاه واقعی ساخته‌شده با اپ قدیمی یا Room انجام نشده است.

این گزارش درستی identity hash و schema کامل Room، کلیدهای یکتا، تمام ارجاع‌ها، رکوردهای orphan، اعتبار رشته‌ها، تنظیمات DataStore، بکاپ، سازگاری همهٔ انواع JSON یا همزمانی در دستگاه را تأیید نمی‌کند. داده‌های اعشاری مالی یا تاریخ‌های نامعتبر فقط گزارش می‌شوند؛ هنوز دربارهٔ نحوهٔ نگهداری بدون اتلاف، نمایش یا تعمیرشان تصمیم اجرایی گرفته نشده و هیچ داده‌ای نباید خودکار حذف یا گرد شود. مسیر نسخهٔ ۱ نیز عمداً بررسی/ارتقا نمی‌شود. برای پشتیبانی واقعی باید migrationهای ۱→۲→۳، حفظ همهٔ ردیف‌ها، تاریخ ISO، ساعات دقیق، rollback و بازیابی تنظیمات با تست Android و fixtureهای واقعی جداگانه پیاده‌سازی شوند.
