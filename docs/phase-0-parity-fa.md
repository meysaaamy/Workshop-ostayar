# فاز صفر: ابزار مقایسهٔ Kotlin و وضعیت پوشش

## آنچه اضافه شد

`parity/kotlin/CompareGolden.kt` خروجی یک پیاده‌سازی را با همهٔ نتایج golden مقایسه می‌کند: ساختار، کلیدها، ترتیب آرایه‌ها، رشته‌ها، مقدارهای null/بولی و اعداد. عددها به‌صورت `BigDecimal` و **بدون تلورانس** مقایسه می‌شوند؛ تفاوت نمایش `1` و `1.0` اختلاف عددی شمرده نمی‌شود. هش APK و هش خود فایل golden کنترل می‌شود و اگر تعداد خروجی‌ها کمتر یا بیشتر باشد، تست شکست می‌خورد. اختلاف‌ها با شمارهٔ سناریو، نام تابع و مسیر مقدار گزارش می‌شوند؛ تعداد پیام‌های اختلاف در نمایش به ۲۰ محدود است، نه تعداد اختلاف‌های شمارش‌شده.

قالب خروجی adapter در فاز آینده باید یک شیء JSON با `goldenSha256` و آرایهٔ `results` باشد. هر عنصر آرایه دقیقاً معادل نتیجهٔ همان مورد در `cases` و با همان ترتیب است؛ adapter باید ورودی‌ها را واقعاً اجرا کند، نه از نتایج مرجع کپی کند. در حال حاضر **adapter و موتور جدید وجود ندارند**.

دستور آزمایش ابزار با JDK و Kotlin در `PATH` یا از طریق متغیرهای محیطی:

```sh
JAVA_HOME=/path/to/jdk KOTLINC=/path/to/kotlinc ./parity/tools/check-kotlin.sh
cd parity && npm ci && npm test
```

آزمون ابزار مقایسه دادهٔ مورد انتظار را فقط برای **خودآزمایی مقایسه‌کننده** کپی کرد، سپس جداگانه اختلاف ۵۹۹۹/۶۰۰۰، اختلاف بسیار کوچک اعشاری، کلید حذف‌شده، خروجی ناقص و هش منقضی را وارد کرد. همهٔ موارد معیوب با وضعیت ناموفق رد شدند. این آزمون‌ها **اثبات همارزی Kotlin با JavaScript نیستند**.
