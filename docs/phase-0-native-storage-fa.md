# ادامهٔ فاز صفر: بررسی ذخیره‌سازی بومی و صدا

## شواهد و محدودیت مهندسی معکوس

`parity/native/decompile_reference.py` با Androguard، شبه‌کد **بهترین تلاش** برای `NativeBridge`، `StateValidator`، `LedgerRepository`، `SettingsRepository`، `Snd` و coroutineهای جایگزینی ذخیره می‌کند. خروجی‌ها سورس Kotlin اصلی یا کد قابل کامپایل نیستند؛ بعضی نوع‌ها و کنترل جریان در شبه‌کد نادرست‌اند و حتی ترتیب چند اعلان محلی ممکن است در بازتولید تغییر کند. دستورهای اصلی DEX، از جمله [coroutine جایگزینی](legacy-replace-coroutine-dex.txt) و [پل](legacy-bridge-dex.txt)، مرجع بررسی‌اند. هیچ‌یک از موارد زیر آزمون روی دستگاه یا دادهٔ واقعی نیست.

`parity/native/check_native_evidence.py` شواهد منتخب را مستقیماً در DEX بررسی و [خلاصهٔ ماشینی](legacy-native-evidence.json) را تولید می‌کند؛ دستور بازتولید پس از نصب `parity/native/requirements.txt`:

```sh
python parity/native/inspect_apk.py
python parity/native/decompile_reference.py
python parity/native/check_native_evidence.py
```

## یافتهٔ مهم: مرز تراکنش قدیمی

در دستورهای `LedgerRepository$replaceStore$2.invokeSuspend`، فراخوانی `RoomDatabaseKt.withTransaction` پیش از فراخوانی `SettingsRepository.writeSnapshot` دیده می‌شود؛ ذخیرهٔ تنظیمات DataStore بخشی از همان تراکنش SQLite نیست. بنابراین **ریسک** ناسازگاری میان Room و تنظیمات در توقف یا خطای بین دو مرحله وجود دارد. این ریسک با تست mock قبلی `replaceWholeState` رد نمی‌شود: آن تست تنها بازگشت متغیر وضعیت وب در حافظه را دید، نه بازگرداندن یک تراکنش Room که ممکن است قبلاً commit شده باشد. وقوع واقعی و پیامد دقیق خطای DataStore باید با fault injection روی دستگاه تأیید شود. نسخهٔ جدید باید برای عملیات حساس، منبع حقیقت و راهکار بازیابی/اتمیک مناسب داشته باشد، بدون اینکه موفقیت کاذب گزارش کند.

## اندازه و اعتبارسنجی

- پل در `saveState`, `validateState` و `saveAutoBackup` حد `83,886,080` را با `String.length` می‌سنجد؛ این واحد **code unit UTF-16** است، نه الزاماً بایت فایل. سپس validator دادهٔ state به‌طور پیش‌فرض سقف جداگانهٔ **۶۷٬۱۰۸٬۸۶۴ بایت UTF-8** را بررسی می‌کند. نباید این دو حد را یکی فرض کرد. `saveAutoBackup` مسیر جداگانه دارد و validator state را فراخوانی نمی‌کند؛ از آرایهٔ `snaps` حداکثر سه مورد آخر را نگه می‌دارد.
- در دستورهای `validatePayouts`، ارجاع به شناسهٔ کاربر بررسی و کاربر ناموجود هشدار می‌شود؛ فراخوانی بررسی نوع کاربر در همان متد دیده نشد. بنابراین فرم، validator و موتور لزوماً قواعد یکسانی ندارند. پذیرش نهاییِ رکورد غیرعادی باید در تست device/native بررسی شود، نه از شبه‌کد به‌تنهایی فرض شود.

## صدای قدیمی

سنتز وب در `Int16Array` و نرخ `22050 Hz` انجام و با `playPcm` ارسال می‌شود. DEX کلاس `Snd.play` تنظیم encoding، نرخ ارسالی و channel mask را روی `AudioTrack` نشان می‌دهد؛ شبه‌کد یک حلقهٔ سه‌تایی track را نشان می‌دهد. فرمت فایل `assets/splash_audio.pcm`، نحوهٔ پخش آن و رفتار واقعی چند نسخهٔ اندروید هنوز نیازمند بررسی مستقل‌اند. صدای جدید هنوز پیاده‌سازی نشده است.

## وضعیت

استخراج شبه‌کد برای هفت کلاس انتخاب‌شده بدون خطای ابزار انجام و شواهد منتخب با DEX کنترل شدند. این به معنی بازبینی کامل ۱۳۴ متد، آزمون native یا بستن فاز صفر نیست. بازبینی ماتریس، گزارش جامع همهٔ مسیرهای پل/validator، سناریوهای باقی‌مانده و گزارش نهایی دروازه هنوز لازم‌اند؛ فاز ۱ شروع نشده است.
