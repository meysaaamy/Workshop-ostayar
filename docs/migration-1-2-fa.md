# شواهد مهاجرت قدیمی ۱ به ۲

از `LedgerDatabase.<clinit>` و کلاس `LedgerDatabase$Companion$MIGRATION_1_2$1` در APK تأییدشده، ۲۰ دستور SQL به ترتیب آرایه استخراج شده‌اند: ده `CREATE TABLE IF NOT EXISTS` و ده `CREATE INDEX IF NOT EXISTS`. متد `migrate` روی فهرست حلقه می‌زند و هر دستور را با `execSQL` اجرا می‌کند. در این ۲۰ دستور هیچ `ALTER`، `INSERT` یا کپی داده دیده نشد. شواهد خام در `legacy-room-migration-1-2-dex.txt` و SQL در `legacy-room-migration-1-2.sql` هستند. **طرح واقعی دیتابیس نسخهٔ ۱ از این شواهد معلوم نمی‌شود**؛ نمی‌توان نتیجه گرفت تمام داده‌های آن نسخه چگونه یا کجا نگهداری می‌شدند. اجرای `migrate` و validation خود Room روی APK و دستگاه نیز هنوز آزموده نشده است.

اهمیت `IF NOT EXISTS`: جدول یا ایندکس هم‌نام اما ناسازگار را اصلاح نمی‌کند. آزمون SQLite روی دادهٔ ساختگی نشان می‌دهد که یک ایندکس هم‌نام با ستون اشتباه پس از اجرای SQL همچنان اشتباه می‌ماند. Room باید طرح حاصل را اعتبارسنجی کند؛ نباید صرف موفقیت اجرای SQL را موفقیت مهاجرت دانست. اجرای اتمیک و حفظ نسخه در آزمون میزبان با تراکنش و `PRAGMA user_version` به‌صورت شبیه‌سازی‌شده انجام شد؛ این PRAGMA در متد استخراج‌شده نیست و رفتار واقعی چارچوب Room هنوز اثبات نشده است. تست جداگانه با جدول ساختگی ناسازگار، rollback تراکنش شبیه‌سازی‌شده و حفظ رکوردهای قبلی را بررسی کرد؛ جدول ناشناس نیز در آزمون حذف نشد. این موارد **مهاجرت ۱→۲→۳ برنامهٔ جدید نیستند**.

```sh
python3 -m venv /path/to/venv
/path/to/venv/bin/pip install -r parity/native/requirements.txt
/path/to/venv/bin/python parity/native/extract_migration_1_2.py
python3 parity/migration/test_legacy_1_2.py
```

## برآورد کار تا مهاجرت واقعی قابل آزمون

با فرض دسترسی به Android SDK/Gradle، emulator یا دستگاه، fixture تولیدشده با نسخهٔ قدیمی و محیط تست قابل تکرار، برآورد فعلی **۴۰ تا ۸۰ ساعت کار مؤثر** است؛ نه وعدهٔ زمانی یا درصد تکمیل:

| بخش | حدود کار مؤثر |
|---|---:|
| استخراج/تأیید fixture نسخه‌های ۱ و ۲، schema و رفتار تنظیمات DataStore روی Android | ۸–۱۶ ساعت |
| تعریف schema نهایی و پیاده‌سازی مسیرهای ۱→۲→۳ و ۲→۳ بدون حذف، با پول صحیح، تاریخ ISO و ساعات قدیمی دقیق | ۱۲–۲۴ ساعت |
| انتقال تنظیمات، کپی امن و طراحی بازیابی در شکست میان Room و DataStore | ۱۰–۲۰ ساعت |
| آزمون Room روی دستگاه، سناریوهای دادهٔ غیرعادی، rollback، قطع عملیات و بازگشایی | ۱۰–۲۰ ساعت |

این تخمین صرفاً تا **مهاجرتی که واقعاً روی Android آزموده شود** است، نه تکمیل Compose، PDF، همهٔ همارزی‌ها یا انتشار. دادهٔ ناسازگار واقعی، ناشناخته‌بودن طرح نسخهٔ ۱، محدودیت محیط یا شکست تست ممکن است زمان را بالا ببرد. در محیط فعلی SDK و دسترسی Gradle/Google Maven موجود نیست؛ پس این پیش‌نیاز زمان نامعلومی اضافه می‌کند. برای نصب به‌عنوان به‌روزرسانی نهایی نیز امضای سازگار با کلید اصلی جداگانه لازم است. طرح نگهداری داده‌های نامعتبر/اعشاری مالی و recovery بین Room و DataStore هنوز تصمیم و آزمون نهایی ندارد؛ هیچ داده‌ای نباید برای عبور از مهاجرت خودکار حذف یا گرد شود.
